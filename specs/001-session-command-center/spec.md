# Feature Specification: Единый CLI-центр AI-сессий

**Feature Branch**: `001-session-command-center`

**Created**: 2026-11-02

**Status**: Draft

**Input**: User description: «Нужен общий командный центр для сессий Grok, Codex, Claude и
Cursor. Сессии теряются, накапливается мусор. Нужно сразу видеть список, номера, источник,
что в сессиях делали и когда они были активны; открывать их в соответствующем CLI через
обычный терминал или Warp, удалять и смотреть статистику, включая токены. Пока только CLI:
вызываешь инструмент и сразу видишь обзор». Дополнение: Grok запускается командой `grok`.

## Clarifications

### Session 2026-11-02

- Q: Если продолжение в новой папке недоступно, предлагать другую папку/отмену или ручную
  инструкцию? → A: Оба варианта совместно с причиной отказа; выбранная сессия и исходное
  расположение её истории сохраняются.
- Q: Что обновлять при фильтрах проекта и даты? → A: Все сессии выбранных источников;
  фильтры проекта и даты ограничивают только вывод.
- Q: Какие идентификаторы показывать в строке обзора? → A: ID менеджера и родной ID;
  длинные значения можно визуально сокращать, полные значения доступны в деталях.

## User Scenarios & Testing *(mandatory)*

Сессия — сохранённый разговор и контекст работы в одном из исходных AI-инструментов.
Владельцем является текущий пользователь компьютера. Менеджер объединяет существующие
локальные истории и передаёт продолжение разговора исходному инструменту.

Все приёмочные сценарии ниже обязательны. Разработка поведения MUST следовать TDD:
сначала тест, подтверждённое падение по ожидаемой причине, затем реализация и рефакторинг.
Проверки MUST использовать искусственные истории без личных данных и реальных секретов.

### User Story 1 - Сразу увидеть свои сессии (Priority: P1)

Пользователь запускает менеджер без параметров и сразу получает общий обзор локальных
сессий Codex, Claude, Cursor и Grok, отсортированный по последней известной активности.

**Why this priority**: Общий список решает главную проблему: сессии больше не нужно искать
вручную в каждом инструменте.

**Independent Test**: Подготовить истории четырёх источников с известными ID и датами,
запустить менеджер без параметров и сопоставить обзор с ожидаемым набором.

**Acceptance Scenarios**:

1. **Given** доступны истории четырёх источников, **When** пользователь запускает менеджер,
   **Then** он видит один список с ID менеджера, исходным ID, источником, названием или
   кратким фрагментом, проектом, последней активностью и доступными действиями. Оба ID
   обозначены раздельно; визуальное сокращение не меняет их полные значения или выбор сессии.
2. **Given** один источник отсутствует, недоступен или содержит повреждённую историю,
   **When** строится обзор, **Then** остальные источники отображаются, а проблема показана
   отдельно и не воспринимается как достоверное отсутствие сессий.
3. **Given** исходный CLI удалён, но история осталась и её формат поддерживается,
   **When** пользователь открывает обзор, **Then** историю можно просматривать, а
   возобновление помечено как недоступное.
4. **Given** сессий нет, **When** пользователь запускает менеджер, **Then** отображаются
   понятное пустое состояние, проверенные источники и возможность указать другое локальное
   расположение истории.

### User Story 2 - Найти сессию и понять, что в ней делали (Priority: P1)

Пользователь находит нужную работу по тексту, проекту, источнику или дате, затем открывает
подробности и доступную историю разговора.

**Why this priority**: Список без содержания не позволяет отличить похожие сессии и выбрать
правильную для продолжения.

**Independent Test**: В наборе похожих сессий найти заданную по фрагменту сообщения и
проверить, что подробности показывают именно её разговор и метаданные.

**Acceptance Scenarios**:

1. **Given** несколько сессий относятся к разным проектам и источникам, **When** пользователь
   задаёт поиск и сочетание фильтров, **Then** остаются только совпадения; видны применённые
   фильтры, число результатов и способ сбросить выборку.
2. **Given** текст встречается только внутри сообщения, **When** пользователь выполняет
   поиск по содержимому, **Then** нужная сессия находится с кратким контекстом совпадения.
3. **Given** выбран ID сессии, **When** открываются подробности, **Then** видны исходный ID,
   источник, расположение истории, проект, доступные даты, сообщения, записанные действия
   инструмента и доступные показатели использования с явными пометками пропусков.
4. **Given** список пересортирован или обновлён и у разных источников одинаковый исходный
   ID, **When** пользователь выбирает ранее показанный ID менеджера, **Then** открывается
   та же сессия, без смешения историй.
5. **Given** разговор длинный или содержит управляющие последовательности терминала,
   **When** пользователь его просматривает, **Then** история доступна частями в исходном
   порядке, а её содержимое не исполняет команды и не управляет терминалом.
6. **Given** искомая подстрока отличается регистром и задано несколько фильтров,
   **When** пользователь ищет сессию, **Then** регистр не влияет на совпадение и выполнены
   все фильтры одновременно. Диапазон включает обе границы, но исключает неизвестные даты;
   смена направления сортировки не меняет ID и не поднимает неизвестные даты перед известными.
7. **Given** в выбранном источнике есть сессии A и B, а фильтр проекта или даты показывает
   только A, **When** пользователь обновляет обзор, **Then** обновляются обе сессии,
   отображается только A, а после сброса фильтра доступна обновлённая B. Сессии невыбранных
   источников сохраняют прежние сведения и время их получения, не помечаются отсутствующими.

### User Story 3 - Продолжить работу в исходном CLI (Priority: P1)

Пользователь выбирает сессию и продолжает именно её в исходном AI-инструменте: в текущем
терминале либо в Warp по явному выбору.

**Why this priority**: Менеджер должен возвращать пользователя к работе с найденным
контекстом, а не оставаться только просмотрщиком истории.

**Independent Test**: Для каждой поддерживаемой комбинации источника и способа открытия
проверить передачу выбранной сессии и её рабочего каталога исходному инструменту.

**Acceptance Scenarios**:

1. **Given** исходный CLI доступен, сессия возобновляема и каталог проекта существует,
   **When** пользователь выбирает продолжение в текущем терминале, **Then** исходный
   инструмент открывает выбранный разговор в соответствующем проекте, сохраняя контекст.
2. **Given** Warp установлен и доступен, **When** выбран запуск через Warp, **Then** в Warp
   открывается тот же исходный CLI с выбранной сессией и каталогом проекта.
3. **Given** CLI или Warp отсутствует, формат не поддерживает возобновление либо запуск
   завершился ошибкой, **When** пользователь выбирает продолжение, **Then** отображается
   причина и доступная альтернатива; новая сессия не выдаётся за продолжение старой.
4. **Given** каталог проекта перемещён или удалён, **When** пользователь продолжает сессию,
   **Then** до запуска предлагается выбрать существующий каталог или отменить действие;
   каталог не создаётся и контекст не подменяется молча. Исходное расположение истории
   сохраняется отдельно от новой рабочей папки. Если продолжение именно этой сессии в
   выбранной папке не поддерживается или не подтверждено для источника, процесс не
   запускается; одновременно показаны причина, выбор другой папки/отмена и инструкция
   ручного запуска. Непроверенные команды не выдаются за работающий способ продолжения.

### User Story 4 - Убрать лишнее и сохранить возможность восстановления (Priority: P2)

Пользователь скрывает ненужные сессии из общего обзора или явно удаляет их локальную
историю в восстанавливаемую корзину. Окончательная очистка корзины — отдельное действие.

**Why this priority**: Уменьшение мусора должно помогать находить работу и освобождать место,
не приводя к случайной потере нужного разговора.

**Independent Test**: На искусственных сессиях проверить скрытие, возврат, удаление,
восстановление, отмену и окончательную очистку; сравнить выбранные и соседние истории.

**Acceptance Scenarios**:

1. **Given** выбраны сессии, **When** пользователь скрывает их, **Then** они исчезают из
   обычного списка, остаются в отдельном представлении скрытых и доступны для возврата;
   исходные истории не меняются, а выбор сохраняется после перезапуска менеджера.
2. **Given** выбраны одна или несколько сессий, **When** запрошено удаление, **Then** до
   изменения данных показаны точные ID, источники, число сессий, известный объём и эффект
   удаления; отказ от подтверждения оставляет данные без изменений.
3. **Given** удаление подтверждено и может быть выполнено безопасно, **When** оно успешно
   завершено, **Then** выбранная история удалена из активного хранилища источника,
   восстановимая копия находится в локальной корзине, а остальные сессии и файлы проекта
   не изменены.
4. **Given** сессия достоверно используется, **When** запрошено удаление, **Then** действие
   запрещено без завершения процесса; менеджер сам не останавливает исходный CLI.
   Если активность неизвестна, пользователь должен явно подтвердить, что сессия закрыта.
5. **Given** есть сессия в корзине, **When** пользователь восстанавливает её, **Then**
   возвращаются её история и принадлежность источнику; конфликт с существующей историей
   не приводит к перезаписи, а завершается понятным отказом.
6. **Given** возникла ошибка копирования, изменения источника или нехватка места,
   **When** выполняется удаление или восстановление, **Then** невосстановимая потеря
   предотвращена, итог каждой выбранной сессии показан отдельно, а повтор операции не
   удаляет другую сессию и не создаёт дополнительную копию в корзине.
7. **Given** пользователь выбирает окончательную очистку конкретных записей корзины,
   **When** подтверждает предупреждение о невозможности восстановления, **Then** удалены
   только выбранные копии; отмена сохраняет их. Самопроизвольной очистки по возрасту нет.

### User Story 5 - Понять объём и использование сессий (Priority: P2)

Пользователь получает сводную статистику и показатели отдельной сессии, чтобы оценить
объём работы и накопленных данных.

**Why this priority**: Статистика объясняет, какие инструменты и проекты используются,
и помогает выбрать данные для уборки.

**Independent Test**: На историях с заранее известными счётчиками и намеренными пропусками
проверить показатели отдельной сессии, фильтры и итоговые суммы.

**Acceptance Scenarios**:

1. **Given** у сессий известны разные счётчики использования, **When** пользователь
   открывает статистику, **Then** видны число сессий, сообщения, доступные токены по
   категориям, период активности и известный объём данных с разбивкой по источнику,
   проекту и периоду последней активности сессии.
2. **Given** часть источников не предоставляет токены, **When** показаны итоги, **Then**
   неизвестные значения не заменены нулём, известный ноль отличается от пропуска, а
   рядом с суммой показаны покрытие и признак неполноты.
3. **Given** история содержит накопительные счётчики, повторные события или отдельные
   категории кеша, **When** считаются итоги, **Then** один и тот же расход не посчитан
   повторно, а несопоставимые категории не объединены без обозначения различий.
4. **Given** применены фильтры, есть скрытые сессии и корзина, **When** открыта статистика,
   **Then** область подсчёта видна явно. Без фильтров учитываются все обнаруженные сессии,
   включая скрытые, но исключая корзину; пользователь может менять выборку.
5. **Given** сессия началась до выбранного периода, но последняя активность попала в него,
   **When** пользователь смотрит её вклад в статистику, **Then** показаны показатели всей
   истории сессии с явной пометкой; они не названы расходом только внутри выбранных дат.
   Количество сообщений включает пользователя и AI, а действия инструментов учитываются отдельно.

### Edge Cases

- Отсутствие доступа к расположению истории и несколько локальных расположений одного
  источника; менеджер не запрашивает повышенные права и не сканирует весь компьютер.
- Повреждённая запись, неизвестная версия формата, пустой разговор и отсутствующие ID,
  даты, проект, модель или счётчики.
- История меняется или исчезает между построением списка, просмотром и выбранным действием.
- Копии записей, повторное сканирование, одинаковые исходные ID разных инструментов и
  новые сообщения после возобновления: существующая сессия не дублируется в обзоре.
- Расхождения часовых поясов: известные даты приводятся к локальному поясу с его указанием;
  дата без достоверного пояса помечается как неоднозначная.
- Наличие последнего события не доказывает, что процесс сейчас работает; недостоверный
  статус текущей активности отображается как неизвестный.
- Проект с пробелами, нелатинскими символами или отсутствующим каталогом; вредоносные
  заголовки и фрагменты истории остаются данными, а не командами.
- Исходный инструмент хранит несколько сессий совместно: удаление одной не затрагивает
  остальные; если этого гарантировать нельзя, действие для неё недоступно.
- Нехватка места для восстанавливаемой копии, прерывание уборки, конфликт восстановления,
  повторное подтверждение уже выполненного действия и частичный успех массовой операции.
- Нельзя достоверно отнести объём общего хранилища к одной сессии: показатель помечается
  как недоступный, а общий объём источника показывается отдельно.
- Очень большой набор сессий или длинная история: обзор показывает прогресс и неполноту,
  поддерживает поиск и навигацию, а подробности не требуют вывода всего разговора сразу.
- Содержимое сессий и корзина могут быть конфиденциальными; они не попадают в отладочные
  журналы, отчёты об ошибках, репозиторий или исходные тестовые данные.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Менеджер MUST предоставлять единый CLI-интерфейс; запуск без параметров MUST
  сразу открывать обзор сессий, доступные действия и сводку состояния источников.
- **FR-002**: Менеджер MUST обнаруживать локальные истории Codex, Claude, Cursor и Grok
  в поддерживаемых стандартных расположениях и позволять пользователю добавить локальные
  расположения. Для Grok целевым исходным инструментом является установленная команда `grok`.
- **FR-003**: Каждая строка обзора MUST содержать устойчивый ID менеджера, исходный ID при
  наличии, источник, название или фрагмент, проект, последнюю известную активность и
  доступность действий. ID менеджера (`display_id`) и родной ID (`native_id`) MUST быть
  обозначены раздельно. Длинные значения можно визуально сокращать с явным признаком
  сокращения; полные значения MUST сохраняться в деталях и JSON. Отсутствующие сведения
  MUST обозначаться явно; сокращение MUST NOT менять выбранную сессию или native resume ID.
  Краткий ID менеджера MUST оставаться однозначным; при коллизии отображается более
  длинный префикс или полное значение.
- **FR-004**: ID менеджера MUST сохранять принадлежность той же сессии между обновлениями
  и перезапусками. Одинаковые исходные ID разных источников MUST различаться, а повторное
  чтение одной истории MUST NOT увеличивать число сессий.
- **FR-005**: Обзор MUST по умолчанию показывать нескрытые сессии от самых свежих к старым,
  помещать неизвестные даты после известных и показывать отдельные счётчики скрытых
  сессий и корзины.
- **FR-006**: Пользователь MUST иметь возможность обновить обзор, искать по метаданным
  и содержимому разговора, сочетать фильтры по источнику, проекту и периоду последней
  активности, менять направление сортировки по последней активности и сбрасывать фильтры.
  Поиск MUST находить подстроку без учёта регистра; фильтры MUST выполняться одновременно.
  Диапазон дат MUST включать обе границы и исключать неизвестные даты. Неизвестные даты
  MUST оставаться после известных при обоих направлениях; равные даты упорядочиваются по ID.
  Обновление MUST охватывать все сессии всех настроенных корней выбранных источников
  независимо от фильтров проекта и даты; эти фильтры MUST ограничивать только вывод.
  Без выбора источников обновляются все включённые источники. Невыбранные корни и записи
  вне фильтра MUST NOT помечаться отсутствующими из-за области отображения.
- **FR-007**: Подробности MUST показывать доступные даты создания и последней активности,
  полные ID менеджера и родной ID, источник, локальное расположение истории, проект,
  модель, сообщения, записанные действия и результаты инструментов, а также показатели
  использования. Длинная история MUST быть доступна частями в порядке событий.
- **FR-008**: Текущее выполнение MUST показываться отдельно от времени последнего
  сохранённого события. Без достоверного подтверждения статус MUST быть неизвестным;
  одно время изменения файла MUST NOT считаться доказательством работающего процесса.
- **FR-009**: Недоступность, ошибка или неподдерживаемый формат одного источника MUST NOT
  блокировать остальные. Возможности просмотра, продолжения, удаления и статистики MUST
  обозначаться отдельно для выбранной сессии с причиной недоступности.
- **FR-010**: Продолжение MUST открывать выбранную существующую сессию в её исходном CLI
  и соответствующем каталоге проекта, без подмены новой сессией. Менеджер MUST проверять
  актуальность выбора перед запуском.
- **FR-011**: Пользователь MUST выбирать текущий терминал или Warp; текущий терминал
  является вариантом по умолчанию. Отсутствие программы, ошибка запуска или недоступность
  продолжения MUST приводить к понятному сообщению, а не скрытой смене инструмента.
- **FR-012**: Если каталог проекта отсутствует, менеджер MUST предложить выбор существующего
  каталога или отмену до запуска; он MUST NOT создавать каталог или выбирать другой молча.
  Исходное расположение истории MUST храниться отдельно от рабочего каталога запуска.
  Смена каталога MUST NOT менять identity сессии или молча переносить её историю.
  Продолжение в новой папке MUST выполняться только при подтверждённой привязке к прежней
  сессии. При неподдержанной или неподтверждённой привязке менеджер MUST отказаться от
  автоматического запуска и одновременно показать причину, другую папку/отмену и ручную
  инструкцию. Инструкция MUST опираться на проверенные возможности CLI и не исполняться
  автоматически; непроверенные флаги и команды MUST NOT предлагаться как рабочие.
- **FR-013**: Пользователь MUST иметь возможность скрыть, показать и вернуть сессии
  одиночно или группой. Скрытие MUST сохраняться между запусками и MUST NOT менять исходную
  историю или мешать продолжению из представления скрытых.
- **FR-014**: До удаления одной или нескольких сессий менеджер MUST показать точный состав,
  источник, последствия и известный объём, затем получить явное подтверждение.
  Подтверждение относится только к показанному набору, а отмена MUST сохранять данные.
- **FR-015**: Успешное удаление MUST убирать выбранную историю из активного хранилища
  источника только после создания пригодной для восстановления локальной копии.
  Файлы проекта, другие сессии и общий рабочий контекст других сессий MUST сохраняться.
- **FR-016**: Менеджер MUST запрещать удаление достоверно активной сессии и MUST NOT
  останавливать процессы. При неизвестной активности MUST требоваться явное подтверждение,
  что сессия закрыта. Если безопасное изменение источника невозможно, удаление недоступно.
- **FR-017**: Менеджер MUST поддерживать просмотр корзины и восстановление выбранной
  сессии с её историей и принадлежностью источнику. Конфликт MUST завершаться отказом
  без перезаписи существующей истории.
- **FR-018**: Окончательное удаление MUST быть отдельным действием только над корзиной,
  с точным набором и явным подтверждением необратимости. Автоматическая очистка и
  автоматическое удаление старых исходных сессий MUST NOT выполняться.
- **FR-019**: Ошибка, прерывание или повтор операции уборки MUST NOT приводить к
  невосстановимой потере или затрагивать другой объект. Для массовых действий MUST
  отображаться отдельный результат каждой сессии и доступный путь восстановления.
- **FR-020**: Статистика MUST включать число сессий, доступное число сообщений, временной
  диапазон, известный объём истории и предоставленные источником токены: входные, выходные,
  кешированные и общий расход, если соответствующие показатели доступны.
  Число сообщений MUST включать пользовательские сообщения и ответы AI; записанные действия
  инструментов MUST учитываться отдельно и MUST NOT увеличивать число сообщений.
- **FR-021**: Статистика MUST поддерживать отдельную сессию и сводки по источнику, проекту
  и периоду последней активности. Область подсчёта MUST быть видна; по умолчанию это все
  обнаруженные неудалённые сессии, включая скрытые, без корзины. Период MUST отбирать
  сессии по последней активности, а показатели MUST относиться ко всей истории выбранных
  сессий. Это MUST обозначаться явно и MUST NOT называться расходом только внутри периода.
- **FR-022**: Неизвестные показатели MUST отличаться от нуля; суммы MUST показывать
  количество сессий с известными значениями и неполноту. Накопительные счётчики, повторные
  события, копии и пересекающиеся категории токенов MUST NOT учитываться повторно.
  Несопоставимые показатели MUST обозначаться отдельно.
- **FR-023**: Указанный временной диапазон MUST NOT называться временем активной работы.
  Размер общего хранилища MUST NOT выдаваться за точный размер отдельной сессии.
- **FR-024**: Обнаружение, просмотр, поиск и статистика MUST работать локально и MUST NOT
  изменять исходные истории или передавать их во внешние сервисы. Сам менеджер MUST NOT
  обращаться к AI-модели для формирования обзора или кратких фрагментов.
- **FR-025**: Менеджер MUST работать в пределах прав текущего пользователя, не расширять
  доступ к исходной истории и защищать локальную корзину от доступа других пользователей.
  Секреты и содержимое разговоров MUST NOT попадать в диагностические журналы или
  репозиторий. Истории и пользовательские пути MUST обрабатываться как данные, а не команды.
- **FR-026**: В случае недоступности источника, незавершённого сканирования или устаревших
  сведений интерфейс MUST показывать это явно и MUST NOT выдавать частичную картину за
  полный актуальный результат.
- **FR-027**: Все пользовательские сценарии и выявленные риски MUST иметь приёмочные
  проверки; изменения поведения и исправления ошибок MUST разрабатываться через TDD.
  Проверки границ источников, продолжения, безопасной уборки и подсчёта статистики MUST
  использовать искусственные сессии с заранее известным результатом.

### Key Entities *(include if feature involves data)*

- **Источник сессий**: исходный AI-инструмент, доступные локальные расположения истории,
  состояние доступности и возможности для конкретных форматов сессий.
- **Сессия**: сохранённый разговор; устойчивый ID менеджера, исходный ID и источник,
  название или фрагмент, проект, известные даты, модель, доступность действий и признак скрытия.
- **Событие истории**: сохранённое сообщение пользователя, ответ, действие инструмента или
  результат; порядок, время и доступное содержание без исполнения записанных действий.
- **Проект**: рабочий контекст и каталог, позволяющие группировать сессии и продолжать их
  в правильном месте.
- **Показатели использования**: значения и категории, область и период измерения,
  происхождение счётчика, известность и полнота; пропуск не равен нулю.
- **Запись корзины и операция уборки**: выбранная сессия, источник, время удаления,
  восстановимая история, результат действия и возможный конфликт при восстановлении.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На контрольном наборе поддерживаемых историй четырёх источников обнаруживаются
  100% ожидаемых сессий без дублей; идентификаторы, источник и известные даты совпадают с
  контрольными данными, а пропуски обозначены как неизвестные.
- **SC-002**: На целевой машине владельца с 10 000 контрольных сессий общим объёмом до 1 ГиБ
  первый содержательный обзор при повторном запуске доступен не позднее 2 секунд;
  первоначальное полное обнаружение занимает не более 10 секунд. До завершения видны
  прогресс и неполнота, а поиск и переходы по списку после обнаружения занимают до 2 секунд.
- **SC-003**: В 9 из 10 контрольных заданий владелец находит заданную сессию и определяет,
  чем в ней занимались, не более чем за 30 секунд без открытия исходных AI-инструментов.
- **SC-004**: В 100% контрольных случаев с выполненными условиями продолжения открываются
  выбранный разговор и проект; для каждого поддержанного источника проверены текущий
  терминал и Warp. Ошибки и недоступность не приводят к незаметному созданию нового разговора.
- **SC-005**: Известные показатели каждой сессии и суммы по контрольным выборкам точно
  совпадают с ожидаемыми значениями; во всех случаях пропусков корректно показаны покрытие
  и неполнота, без двойного учёта.
- **SC-006**: Во всех контрольных сценариях скрытия, отмены, удаления, восстановления,
  прерывания и повторного действия соседние сессии и файлы проектов остаются неизменными.
  Восстановление возвращает исходное содержание выбранной истории; очистка корзины
  уничтожает только явно подтверждённые копии.
- **SC-007**: Во всех сценариях обнаружения, поиска, просмотра и статистики исходные истории
  остаются неизменными и содержимое не передаётся во внешние сервисы.
- **SC-008**: Во всех контрольных отказах одного источника доступны здоровые источники;
  ни ошибка чтения, ни незавершённое обнаружение не отображаются как достоверный пустой список.

## Assumptions

- Первая версия предназначена для одного владельца и его локальных AI-сессий на macOS.
  Многопользовательская работа, удалённые машины и другие ОС пока вне объёма.
- Codex, Claude, Cursor и установленный `grok` — четыре целевых источника первой версии.
  Поддерживаемые версии форматов и реальные возможности каждого источника MUST быть
  проверены и зафиксированы при планировании; неподдерживаемая возможность обозначается
  честно и не считается реализованной заглушкой.
- Возможность чтения зависит от существующей доступной истории; продолжение дополнительно
  зависит от исходного CLI, его условий доступа и наличия нужного контекста. Менеджер не
  восстанавливает разговоры, уничтоженные источником до первого обнаружения.
- Основной способ работы — вызов CLI и взаимодействие с обзором в терминале. Отдельный
  графический или веб-интерфейс, фоновая синхронизация вне TUI, облачное хранилище и перенос между
  компьютерами в первую версию не входят.
- Текущий терминал — способ продолжения по умолчанию; Warp — дополнительный вариант по
  явному выбору. Менеджер не устанавливает исходные инструменты и Warp автоматически.
- Скрытие действует только в менеджере; удаление меняет локальную историю источника и
  создаёт локальную корзину. Удаление облачных копий, очистка памяти активного процесса и
  гарантированное безопасное стирание носителя вне объёма.
- Никаких автоматических сроков удаления истории и корзины нет. Окончательная очистка —
  осознанное действие владельца; повторная проверка доступности обязательна перед изменениями.
- Предпросмотр и краткое описание используют уже сохранённые названия и фрагменты.
  Генерация новых AI-резюме, платные обращения, расчёт стоимости по внешним тарифам,
  массовое переименование, метки, избранное и экспорт отложены за пределы первой версии.

### Уточнения после приёмки — 2026-11-03

- Стандартное удаление Claude не требует ручного TOML: manager определяет поддержанную
  runtime version через --version и проверяет совместимую форму каждой записи JSONL.
- Ошибка optional history/usage одной сессии не скрывает metadata или здоровые сессии.
- F5 обновляет обзор, o открывает native CLI, r восстанавливает запись только в корзине.
  Delete/Move to trash означает восстановимый перенос; Purge — отдельное окончательное удаление.
- Grok usage.json.session содержит totals; отсутствие файла остаётся not_recorded.
  Cwd проекта и расположение native history показываются раздельно без переугадывания пути.

### Уточнения native совместимости — 2026-11-03

- Отсутствие optional Cursor meta.json не скрывает session SQLite metadata. Cwd берётся
  из проверенного соседнего workspace context либо остаётся unknown. Binary hash refs
  и shell turns читаются; неизвестный блок не скрывает последующую доступную историю.
- Grok/Cursor поддержанные executable versions определяются без ручного TOML; shared
  indices, неизвестная topology и activity guards по-прежнему блокируют небезопасную уборку.
- Codex 0.166.0 paginated resume использует native ID и CODEX_HOME без обязательного
  rollout и допускает новый существующий cwd. Прежний locator и ID сохраняются. Native
  gate выполнен только на изолированных искусственных сессиях с offline provider.
- Human CLI/TUI показывают объяснение причины и дальнейшее действие; JSON reason/error
  codes сохраняют совместимость. Unknown metrics не превращаются в вымышленные значения.
- Warp delivery не подтверждает запуск. После фактического failed runtime gate
  пользователю указывается Current terminal; native Codex cascade cleanup остаётся
  unavailable до доказанной точной границы операции и восстановления.

### Фильтрация и сортировка обзора — 2026-11-04

Расширение FR-006: пользователь сразу видит кнопку Filters / sort и сводку текущей
выборки. При длинном списке и размере 80x24 таблица прокручивается внутри оставшегося
пространства; кнопки и поиск остаются видимыми. Можно выбрать несколько источников (OR), подстроку проекта, подстроку модели,
activity active/inactive/unknown, период последней активности и visible/hidden/all.
Разные фильтры и буквальный поиск объединяются AND. Activity берётся из сохранённого
наблюдения; фильтр не переопределяет неизвестный статус. Пустой выбор источников в TUI
не применяется: требуется хотя бы один источник, Reset возвращает все.

Сортировка: last activity, created, source, project, title/preview, native ID, manager ID,
model, activity и известный размер. Направление задаётся отдельно asc/desc; для дат и
размера default desc, для текстовых полей asc. recent/oldest сохраняются как CLI aliases.
Unknown/пустые значения остаются после известных в обоих направлениях, равные значения
разрешаются стабильным session_uid. Сортировка применяется ко всей выборке до pagination.
TUI поддерживает выбор в диалоге и клик заголовка существующего столбца: повторный клик
меняет направление. Sort сохраняет выбранный ID и batch; смена фильтра снимает batch
только с исчезнувших из видимой выборки записей, чтобы действия не затрагивали их скрыто.

CLI list/refresh используют те же фильтры/сортировку, stats — те же фильтры. Новые
параметры валидируются до открытия каталога/сканирования. Refresh перечитывает все
сессии выбранных source roots, независимо от model/activity/project/date/query фильтров.
Настройки действуют в текущем TUI, переживают refresh; Escape/Reset all возвращает
default selection/search/sort. Native source data и stored session schema не меняются.

Приёмка: (1) два источника+project+model+activity+период дают точное пересечение;
(2) одинаковый сортированный набор CLI/TUI и корректная pagination; (3) unknown last и
стабильные ties в обоих направлениях; (4) видимая кнопка/сводка, header toggle, reset,
invalid inputs и отсутствие off-screen batch targets проверяются Textual Pilot;
(5) фильтр не сужает refresh/reconciliation; (6) warm view остаётся в SC-002 <=2 s.


### Native Codex Archive / Unarchive — 2026-11-05

FR-028: пользователь может отдельно архивировать Codex 0.166.0 paginated сессию и вернуть
из архива, не удаляя историю и не создавая manager trash. Archive затрагивает выбранную
сессию и её spawned descendants; preview показывает точный набор и исходные archived
flags. Unarchive также каскадирует; coordinator возвращает исходные flags подтверждённого набора в порядке parent-before-child, сохраняя ранее
архивированных потомков. Архив не освобождает место на диске и доступен отдельным списком.

Профиль требует проверенного native executable/home, одной доказанной location, полного
графа, отсутствия известной активности и обязательного --assert-closed для всего набора
на время операции. Это предусловие закрытости, не native transaction/revision lock.
Changed graph/state/history перед первым вызовом отменяет commit. После каждого native
вызова проверяется фактический результат: success RPC не доказывает полный cascade.
Durable manager journal сохраняет точные IDs/prestates и позволяет retry после рестарта;
частичный сбой не становится complete. Новые IDs не добавляются при retry. Неизвестный
profile/граф/alias или известный writer блокируют действие. Никаких direct native DB DML,
постоянного delete или новых AI turns при пользовательском Archive/Unarchive.

Приёмка: родитель + два потомка (один уже archived) + независимый сосед; preview/cancel,
изменение графа после preview, known active, lost response после native change, partial
cascade, restart/retry, сохранение IDs/history/hidden state и исходных archived flags.
CLI и TUI имеют отдельные явные Archive/Archived/Unarchive действия; подтверждение не
переиспользует trash token. T118 для гарантированного permanent/trash cleanup не закрывается.


### Автообновление и страницы TUI — 2026-11-11

FR-029: Пока открыт TUI, автообновление списка включено по умолчанию: каждые 5 секунд
после завершения предыдущего цикла worker проверяет stat файлов/каталогов локальных
источников без чтения неизменившихся историй. Изменённые источники проходят существующий
discovery pipeline; все корни провайдера, включая aliases, обновляются вместе. Только

Переключатель Auto refresh и состояние последнего обновления видимы в обзоре. Ошибки

откладывается при любом диалоге. Open/trash/archive приостанавливают автоцикл, дожидаются
readers и повторно проверяют исходные UID; действие не переключается на строку под курсором.

FR-030: Catalog.query_page(QuerySpec, limit, offset) возвращает rows, total и revision
согласованной выборки. SQL выполняет фильтрацию, буквальный Unicode поиск и сортировку
до LIMIT/OFFSET, десериализуются только строки страницы. Сохраняются unknown-last,
ascending UID ties и глобальные короткие IDs. Первая страница — 100 строк; последние
20 загруженных строк запускают добавление следующих 100, одинаковые запросы объединяются.
Прокрутка мышью и клавиатурой поддерживаются; обзор показывает Loaded N of M / Loading.
При изменении каталога обновляется загруженный диапазон с сохранением UID/scroll; при
перемещении выбранного UID загружается содержащий его диапазон. Смена фильтров начинает
первую страницу. Batch сохраняет все соответствующие фильтрам UID, включая незагруженные;
подтверждение опасного действия закрепляет точный набор и проверяет его актуальность.

Приёмка: synthetic создание/изменение/исчезновение; aliases; неизменившиеся истории;
ошибка и retry 30s; сериализация/очередь scan; диалоги/details; shutdown с активным reader;
скролл, последняя страница без дублей/пропусков, SQL/Python parity для всех сортировок,
Unicode/date/scope/search фильтров, revision, выбор вне страницы и безопасный batch.
Управляемые часы тестируют интервалы без ожидания wall clock. SC-002 остаётся <=2 s
для первого кешированного экрана/навигации и <=10 s для полного контрольного discovery.
Native formats и schema 4 не меняются; native gates и T118 остаются отдельными задачами.
